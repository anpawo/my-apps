**Coexistence.** Install `VCX Rust Preview.app` with a distinct bundle ID, config, cache, Fleet test namespace and default runtime home. Keep the Swift bundle and updater target available while old workers depend on them. Route by session, with an explicit handover command rather than an app-wide toggle. Start with isolated fixture workers and fresh provider threads. For a live handover, validate the record, cwd, attachments and target frontend before touching the lease. Quiesce outgoing actions, settle or reconcile in-flight requests, checkpoint the draft and window generation, then attach the new frontend to the **existing** socket. Make it writable only after applying the snapshot. If the new frontend fails after lease transfer, have the old one reattach and restore from the worker. Preserve a common ownership lock for real provider threads across both runtime namespaces, and give each persisted record one writer. **Can Rust adopt a Swift worker’s running child?** Technically yes, if the Swift worker `execv`s a compatible Rust image in the same process. Darwin preserves descriptors with close-on-exec cleared. The Swift manifest also carries the listener, locks, session and provider state, sequencing and unread bytes. Its adopter currently supports Claude and Codex, and its failed-adoption path can terminate a child. A separately launched Rust worker cannot acquire those pipes by reading their integer values from a file. Skip cross-language live adoption for this migration. Handover already preserves the agent, and draining workers gives a reversible path. Revisit Rust-to-Rust idle adoption only if measured cold-resume costs justify maintaining an adoption ABI. [Darwin `execve`, read 2026-11-25](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/execve.2.html), [Swift manifest and adoption, read 2026-11-25](/Users/mr/self/my-apps/vcx/Sources/VCX/RuntimeSwap.swift:17), [Swift server freeze, read 2026-11-25](/Users/mr/self/my-apps/vcx/Sources/VCX/RuntimeServer.swift:325).

## 3. What to rebuild better

**Protocol.** Keep v1 byte- and behavior-compatible during coexistence. Preserve newline JSON, private same-user sockets, the 32 MiB frame and 64 MiB buffer bounds, contiguous action sequences, receipt conflict behavior and reserved capacity for interrupts. Test fragmented lines, slow readers, competing attaches, lost replies and oversize snapshots. Give every retry its original sequence and action bytes. After a worker crash, reconcile uncertain acceptance against durable state and provider history before resending. When both Rust ends ship, add a negotiated v2 only where it earns its keep. I would use typed operations, explicit `baseRevision` and `revision`, a resync response, and paged or chunked initial history to remove the single-frame snapshot ceiling. Retain newline JSON. Keep runtime negotiation independent of snapshot format, swap ticket version and page contract. The existing Swift `hello` requires `protocol: 1`, so the Swift path must still send that exact handshake. [Swift transport limits, read 2026-11-25](/Users/mr/self/my-apps/vcx/Sources/VCX/RuntimeTransport.swift:22), [Swift handshake and action ordering, read 2026-11-25](/Users/mr/self/my-apps/vcx/Sources/VCX/RuntimeServer.swift:125).

**State.** Model `Row`, `Item`, `Turn`, `Question`, `Approval`, `DraftPiece` and stable IDs explicitly. Store draft pieces as text or references to image, paste and command chips. Keep provider-specific JSON at the adapter boundary and in bounded diagnostics where needed. Recognize unknown informational events without dropping the turn, preserve unknown items in a safe fallback representation, and surface unknown interactive requests as unsupported. Keep question and option IDs opaque across reconnects. Give the reducer explicit inputs for retry, timeout, cancellation and provider exit. Restore older archives with versioned readers and retain their original files until round-trip checks pass.

**Rendering.** Start from the worker’s full v1 snapshot, then apply ordered patches to a Rust replica. Send the page a bounded initial projection and incremental, revisioned patches. Coalesce repeated changes to the same item and wake the main loop once per pending batch. Schedule at most one DOM commit per animation frame when visible, with an explicit flush path for hidden views and tests. Preserve sequential actions and question transitions independently of render cadence. Virtualize variable-height rows using stable IDs, measured heights and overscan. Anchor by row ID and pixel offset, follow the tail only when already at the tail, and search the full Rust text index so unmounted rows remain searchable. Keep native selection and cross-row copy in the acceptance suite.

Parse Markdown in Rust with `pulldown-cmark`, using explicit options for tables and other required extensions, then sanitize with a tailored `ammonia` allowlist. Cache sanitized HTML in a bounded frontend-side Rust cache keyed by content and parser/sanitizer policy version. Parse the active streaming item at a controlled cadence and parse finalized items on demand. Keep raw Markdown in durable storage. Extract chart fences into typed chart descriptors before assembling transcript HTML. Route attachment and file-link actions by validated IDs. [pulldown-cmark, read 2026-11-25](https://docs.rs/pulldown-cmark/latest/pulldown_cmark/), [Ammonia, read 2026-11-25](https://docs.rs/ammonia/latest/ammonia/).

**Concurrency.** Use a small Tokio runtime for sockets, provider pipes, polling and cancellation, with one serial state owner per worker. Keep blocking disk work and Markdown parsing off the AppKit thread. Use byte-budgeted queues as well as message-count bounds. The frontend can use one background I/O runtime for all windows. Have it send a coalesced wakeup through `EventLoopProxy`. AppKit, tao and wry stay on the main thread, and a command whose bounded queue is full gets an explicit busy result. Await provider exits and make shutdown and cancellation explicit. [Tokio process and channels, read 2026-11-25](https://docs.rs/tokio/latest/tokio/process/), [bounded mpsc, read 2026-11-25](https://docs.rs/tokio/latest/tokio/sync/mpsc/), [tao event proxy, read 2026-11-25](https://docs.rs/tao/latest/tao/event_loop/struct.EventLoopProxy.html), [wry main-thread check, read 2026-11-25](https://raw.githubusercontent.com/tauri-apps/wry/dev/src/wkwebview/mod.rs).

**Template and charts.** Define independent `pageApiMajor` and `pageApiMinor` versions, a `ready` handshake, typed snapshots and patches, and a small vocabulary of validated UI intents. Serve immutable generations of disk assets through an app-owned scheme. Stage edits together, validate the candidate with the hidden verifier, then reload open windows from the same generation. Rehydrate from the Rust replica and restore view state. Promote after acknowledgement, roll a failed window back to cached last-good assets, and keep a bundled rescue template. Discard messages from obsolete page generations.

Give chart iframes `sandbox="allow-scripts"` without same-origin, navigation or popup privileges. Deny direct network loads through chart CSP and host navigation policy. Use a per-frame message channel scoped to the current chart, with a subscription-only API for `vcx.live`. Verify the trusted top frame before accepting privileged native messages. The core owns scheduling, destination and redirect validation, the URL allowlist, response size and time bounds, and cancellation when the chart is removed. Give the frame data replies only. Test the boundary inside wry, including across iframe navigation and template reload. [HTML iframe sandbox, read 2026-11-25](https://html.spec.whatwg.org/multipage/iframe-embed-object.html), [WebKit script message frame metadata, read 2026-11-25](https://developer.apple.com/documentation/webkit/wkscriptmessage/frameinfo).

**Composer.** Use an `NSTextView` through objc2 in a native sibling region reserved below the web view. This keeps the composer and transcript on separate hit-test surfaces. AppKit owns the editor, text selection, undo, input context, marked text and pasteboard. The Rust draft model owns committed text and chip references. Defer external draft replacement during composition and prevent Return or palette shortcuts from sending while marked text is active. Keep image and long-paste conversion native, with typed actions for send and command selection. When a question replaces the editor, preserve its draft and restore focus deliberately on exit. [Apple text editing and marked text, read 2026-11-25](https://developer.apple.com/library/archive/documentation/TextFonts/Conceptual/CocoaTextArchitecture/TextEditing/TextEditing.html).

**Live update.** Ship frontend replacement first. Preflight the signed build, verify restore records, then reattach it to existing workers. Treat WebContent termination as a page restart from the Rust replica. For worker updates, start new sessions on the new binary and leave old workers running until their sessions close or reach an approved cold-resume point. If idle exec adoption becomes worthwhile, version its manifest, validate the candidate before exec and exercise partial records, inherited descriptors, locks and failure after exec with fixture agents. Keep the previous bundle and worker binary available for rollback. [WebKit content-process termination callback, read 2026-11-25](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate(_:).md), [Swift swap preflight, read 2026-11-25](/Users/mr/self/my-apps/vcx/Sources/VCX/RuntimeSwap.swift:97).

## 4. What to leave behind

Drop the SwiftUI transcript host cells, the separate `WKWebView` for each chart and the production check dispatcher. Merge the repeated provider-to-Codex event translation into adapter-to-domain mappings plus one legacy codec. Keep archive formats and import behavior while removing duplicate parsing only after fixture parity. Leave the current Swift frontend and worker callable for rollback until their last live sessions drain. Keep Python packaging, updater orchestration and archive or cleanup helpers wherever they already work, then change their invocation points as needed.

Keep the composer, responder and input routing, pasteboard, open and save panels, Finder and file actions, and WebKit frame validation and snapshots native through a narrow objc2 module. Let tao own the ordinary window and event lifecycle. Keep transcript, find, status and task panels, and chart presentation in the template.

## 5. Windowless verification

Use an **unordered tao window** with production content geometry and `WindowBuilder::with_visible(false)`. Build wry as a child, give it nonzero bounds, and leave the view itself laid out in the window. Pump the real main loop. The macOS backend reads `ns_view.window()` during construction, so a detached view is a poor basis for the production wry test. A detached raw `WKWebView` can be a diagnostic for WebKit alone. For DOM reads, use `evaluate_script_with_callback` and assert structured JSON after the page acknowledges a revision. - **Timers and frames.** Upstream WebKit has distinct visually idle or occluded rendering and DOM timer policies. Wry’s `BackgroundThrottlingPolicy::Disabled` maps to WebKit’s inactive scheduling policy where supported, so test it as a harness option. Drive readiness through acknowledgements and deadlines outside JavaScript, and sample animations at controlled times while draining the run loop. Measure actual macOS 26 behavior before relying on autonomous timers or `requestAnimationFrame` in a hidden view. ## 6. Risks and stop rules

| Risk | Early signal | Stop rule |
|---|---|---|
| WebContent placement or hidden rendering differs from the design | Views share a content process, a chart adds one, hidden captures go blank, the Dock appears or the test takes focus. | Block live attachment until the hidden shell passes. Test a fresh nonpersistent website data store per view as a candidate and correlate content processes to windows with WebKit diagnostics, including after reload and chart creation. Apple says separate `WKProcessPool` instances no longer affect behavior, so pool counts prove nothing about process counts. If the pinned stack fails the required mapping, keep the canary isolated until a supported topology passes. [Apple process pool, read 2026-11-25](https://developer.apple.com/documentation/webkit/wkprocesspool.md), [Apple nonpersistent data store, read 2026-11-25](https://developer.apple.com/documentation/webkit/wkwebsitedatastore/nonpersistent().md). |
| Ownership, retries or recovery diverge | A stale frontend can write, a send happens twice, a draft disappears, or the same provider thread opens twice. | Any occurrence blocks migration for that provider. Re-run lost-reply, killed-frontend, worker-crash and rollback fixtures in both directions before another live handover. |
| Native interaction or chart isolation regresses | IME Return submits, a chart steals composer focus, wheel input reaches the transcript behind the chart, or a chart accesses an ungranted capability. | Keep that feature off the canary until the matching native interaction or isolation check passes. Keep Swift as the fallback for sessions that need it. |
| The process split costs too much at 13 windows | Growing queues or DOM nodes, slow attach, memory drift or delayed input while all sessions stream. | Establish Swift and Rust baselines on the same Mac with the same history, worker count, provider stream and power mode. Report idle and peak footprint and CPU for frontend, workers, agents, WebContent and attributable WebKit services, plus p95 attach, update-to-DOM and input latency. Block default rollout on unbounded growth or a repeatable breach of the predeclared budget. The existing Swift harness times offscreen raster and samples frontend and worker RSS, so extend attribution before comparing totals.
