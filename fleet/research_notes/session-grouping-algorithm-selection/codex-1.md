For unresolved text, start with weighted lexical candidate retrieval: [SQLite BM25](https://www.sqlite.org/fts5.html) supports column weights for names, aliases and descriptions. It is explainable but misses paraphrases. Fixed embeddings with exact search are the next challenger: [Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html) documents direct similarity search for small corpora, avoiding an approximate index. Semantic similarity still does not establish ownership. A small supervised classifier needs representative [labeled examples](https://fasttext.cc/docs/en/supervised-tutorial.html), including new-project handling. Runtime LLM classification offers contextual interpretation, potentially including images with a suitable model, but introduces timeout, variability and privacy concerns. Use only an already authorized local or subscription route, constrain outputs to catalogue IDs or abstention, and validate fallback behavior.

I expect rules and lexical retrieval to minimize latency, memory and maintenance while keeping evidence local; those are architectural expectations, not measurements. Embeddings add model memory and lifecycle work; supervised models add labeling and retraining; remote LLMs disclose supplied context. Accuracy, coverage and assignment stability must be measured separately.
