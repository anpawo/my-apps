# Cross-examination after the blind round

All six research responses were read in full. These are disputed or singly raised claims, not adopted requirements. Google appears through two routes and Meta through two services; their agreement is not independent-provider replication.

1. **Embeddings in the initial release:** Codex recommends lexical-first and embeddings as a challenger; both Gemini routes, Muse and Meta propose hybrid retrieval immediately while acknowledging that its benefit is unmeasured; Qwen treats embeddings as a secondary filter. Does any Fleet evidence establish that their added complexity improves the error/coverage frontier?
2. **Assignment ownership:** Codex, Gemini web and Meta put authoritative grouping in Fleet; Antigravity and Muse put it in VCX; Qwen leaves the session-record owner unclear. Newly read local evidence: `SessionRegistry.swift:27,111` combines terminal sessions with VCX sessions and `ProcessScanner.swift:56` recognizes Claude and Codex terminal sessions. An assignment strategy must cover those input adapters too.
3. **Precision and performance claims:** Antigravity asserts sub-millisecond rules, zero memory, sub-150 MB embeddings, 20 ms latency and a minimum of 200 labels; Qwen proposes a 5% error cutoff. No such figures were measured or established by the brief's sources. Gemini web calls provenance the highest-precision signal; that is a plausible hypothesis, not a measured result. Retract or provide directly applicable evidence.
4. **What evolution can optimize:** Qwen restricts the tools to work inside correctly assigned sessions and says valid initial correctness is presupposed; other reviewers allow offline grouping-policy optimization. Current GEPA documentation explicitly supports code and configurations: https://github.com/gepa-ai/gepa . The existing local equality-only judge is for other tasks, not an existing grouping-accuracy evaluator. Distinguish that contract from a new independently labeled grouping objective.
5. **Simple numerical tuning as a baseline:** Most reviewers suggest LLM evolution for weights and thresholds. New source: https://www.jmlr.org/papers/v13/bergstra12a.html makes random parameter search a useful baseline on its studied tasks. It does not prove a Fleet winner, but why pay for code evolution if the search space is only a few numeric parameters?
6. **Abstention and provenance are conditional:** Qwen suggests the home directory as an image-only fallback; others prefer an unresolved category. A working directory may be inherited or temporary; dependency code can sometimes be the explicitly requested target. Hard pins, task intent, ambiguity and coverage must be considered instead of treating any path or all vendor exclusions as universally correct. Ranking scores and margins are not calibrated probabilities.
7. **Evaluation time and labels:** Antigravity restricts features to turn zero, while the application also needs later reassignment. Meta disallows later corrected directories as labels. Evaluate decision-time prefixes at multiple turns; later human adjudication can supply ground truth, while future actions must not leak into features. Current assignments and later edit destinations are weak labels, not unquestionable task intent. Keep related sessions and duplicates together across splits, with a locked final test and separately reported novel-project behavior.
8. **Falsifiers and objectives:** Compare false assignments at matched coverage, with cold/warm end-to-end tail latency, memory and assignment churn. Abstaining on everything must not win; lexical retrieval need not beat every LLM on raw accuracy to be preferable under a resource constraint. No numerical threshold is currently justified. State what would falsify the initial recommendation, not only what would falsify an unrelated path-only baseline.
9. **Images and live LLM use:** The existing router receives prompt text and a catalogue, not image bytes. A vision fallback or OCR path would be a separate integration, and a vague screenshot does not itself identify a project. Claude is currently unavailable in the connectivity checks. Do not assume an available multimodal fallback or silently substitute a billed provider.
10. **Hierarchy, event normalization and stale state:** Fleet intentionally has both a specific `dirName` and an outermost `groupKey`, with `.fleet` splits. Preserve that display policy. Normalize successful structured events across providers, keep dependency reads weak, use stable session identities and catalogue versions, and re-evaluate on meaningful events rather than every UI refresh. A more sophisticated ranker cannot recover an event or a target folder missing from its inputs.

Each reviewer receives every other blind answer and this list, must attack its own claims, and may change position only with new source evidence or the newly supplied code observations. Agreement without such evidence is recorded as yielded rather than independent verification.
