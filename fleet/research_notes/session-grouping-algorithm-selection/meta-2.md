Final initial architecture: Fleet owns one versioned assignment record with project id, evidence, source, confidence proxy, timestamp, and override state. Adapters for VCX, terminal, Claude, and Codex emit normalized events: explicit correction, project selection, successful cd, file edit, Git operation, and weak read. Deterministic provenance resolves explicit evidence first, then longest-path Git or .fleet boundary matching for nested projects. Lexical BM25 over catalogue names, aliases, paths, and descriptions, documented at https://www.sqlite.org/fts5.html, handles unresolved text. Embeddings remain an offline challenger using exact search for a small corpus, per https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html, fused only if it wins on the locked test. Runtime LLM classification is a bounded fallback over top candidates, using an already authorized route, with strict output to catalogue ids or abstention. Ambiguity abstains to unresolved rather than forcing a false assignment. Execution cwd stays separate from grouping cwd.

Offline plan: first build the labeled decision-time evaluation set and baseline. Then run random search over BM25 weights, thresholds, and abstention rules. Only then test OpenEvolve, ShinkaEvolve, or GEPA for structural policy or prompt optimization against the same labeled evaluator, with Pareto reporting of false assignments, coverage, latency, memory, and churn.
