RETAIN PROVENANCE-OWNERSHIP IN FLEET. The local code facts confirm `SessionRegistry.swift` aggregates inputs from multiple adapters, including terminal sessions and VCX streams. Placing the single authoritative assignment in Fleet's session store ensures a unified state regardless of whether the input originated from a shell or an external provider. This resolves the ambiguity regarding where the label lives, ensuring that execution `cwd` (mutable) does not dictate logical grouping (stable).

REVISE EVOLUTIONARY TOOL ROLES. OpenEvolve, ShinkaEvolve, and GEPA are reserved strictly for offline hyperparameter tuning and prompt optimization after a labeled ground truth is established. They cannot invent labels for unlabeled sessions. GEPA's strength in configuration reflection applies here only to optimizing BM25 weights or RRF fusion thresholds, not to the initial classification of raw session streams. Using them for runtime inference introduces unnecessary latency and non-determinism that destabilizes the grouping pipeline.

RETAIN HYBRID RETRIEVAL FALLBACK. For cold-start sessions lacking explicit Git ancestry or `.fleet` markers, a local hybrid system using SQLite FTS5 BM25 combined with exact vector search via Reciprocal Rank Fusion is optimal. This leverages the small project catalogue without requiring heavy model inference. It offers explainable rankings and low memory overhead compared to embedding retraining pipelines. The top match must exceed a confidence margin; otherwise, the system abstains rather than forcing a false label.

REVISE IMAGE-ONLY HANDLING. With current connectivity checks showing Claude unavailable for vision tasks, assume text-only input. Image-only sessions should default to an "Unassigned" bucket or inherit the home directory only if textual transcript evidence exists. A vague screenshot without OCR paths does not provide sufficient signal and risks misrouting.

RETAIN DETERMINISTIC BASELINE FIRST. Simple numerical tuning of thresholds on a small parameter grid serves as a viable baseline before committing to evolutionary algorithms. Evolutionary search is justified only when simple tuning fails to push the error rate below a specific bound, given the small search space of weighting parameters and abstention thresholds.

FINAL ARCHITECTURE AND EVALUATION PLAN. Deploy the provenance-first router with BM25+embedding fusion as the cold-start engine. Store the final assignment in Fleet's session record. Normalize events from all adapters into this single store. Evaluate using a time-ordered split of human-verified labels, ensuring no future edits leak into decision features. Measure false assignments separately from abstentions.

The critical unresolved question is the precise confidence threshold where lexical retrieval loses to LLM classification under resource constraints, but current evidence suggests lexical+provenance suffices for high precision. The falsifier is a leakage-free evaluation showing that the hybrid system produces significantly more false assignments than the provenance-only baseline at equal coverage. If this holds, strip the embedding layer and rely solely on deterministic rules and FTS5 until labeled data permits supervised learning.
