The most robust initial production approach combines deterministic provenance rules with lexical retrieval, reserving machine learning models for post-hoc correction only after establishing labeled ground truth. Deterministic path rules must prioritize the Git repository root and explicit `.fleet` split folders reported by VCX as absolute anchors. This handles nested projects naturally if the Git ancestry chain is preserved in the session metadata, ensuring a single authoritative assignment lives within the session record linked to its root directory. Lexical ranking using BM25 against a curated project catalogue serves as the primary inference engine when provenance data is missing or ambiguous, offering high recall without semantic drift. Fixed embeddings with exact search can act as a secondary filter for specific known projects but risk false negatives if code vocabularies diverge between sessions.

OpenEvolve, ShinkaEvolve, and GEPA currently play at best an auxiliary role rather than the core grouping engine. OpenEvolve excels at programmatic improvement given a fixed fitness function, which implies pre-existing correctness; it cannot solve the cold-start problem of assigning unverified sessions to correct unlabeled clusters. ShinkaEvolve and GEPA offer adaptive optimization and reflective search but rely on iterative scoring that presupposes a valid initial state. Using them for routing introduces unnecessary latency and depends on an evaluator that may itself be misaligned if the project context is wrong. They should remain tools for code evolution within correctly assigned sessions, not classifiers for directory assignment.

Ambiguity resolution requires a tiered strategy. First, enforce strict Git ancestry checks. Second, apply BM25 scoring weighted by file modification time and frequency to distinguish active projects from incidental dependency reads. Topic changes can trigger periodic re-scoring against the catalogue. Sessions with image-only context lack textual anchors for lexical search; these require a default fallback to the user's home directory or an LLM-based classifier trained on labeled examples once available, accepting higher latency as a trade-off for coverage.

Before claiming improvement, the evaluation contract must define a "golden set" of sessions with verified directories and known project roots. Splits must separate training (for any supervised models) from test sets without time-of-decision leakage. Metrics must weight false assignments heavily against abstention rates, rather than optimizing pure speed. The current evidence lacks a sufficiently large, leakage-resistant labeled dataset to prove supervised classifiers outperform lexical methods for this specific task.

The critical decision unprovable by current data is the exact threshold where lexical confidence yields to runtime LLM classification. A concrete falsifier for the recommended hybrid approach is a random subset of sessions processed exclusively through Git ancestry rules where error rates exceed 5 percent, proving deterministic anchors are insufficient alone; alternatively, running a BM25-only pass on the golden set must show accuracy significantly higher than any current LLM prompt result to justify retaining it as the default.
